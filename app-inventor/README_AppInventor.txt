MIT APP INVENTOR VERSION - Practicals 1 to 10
=============================================

HOW TO IMPORT AND RUN
1. Go to ai2.appinventor.mit.edu and sign in with a Google account.
2. Projects > Import project (.aia) from my computer > pick one .aia file.
3. Test on phone: install "MIT AI2 Companion" from Play Store > Connect > AI Companion > scan the QR code.
   (or Connect > Emulator, or Build > Android App (.apk) to get an installable APK)
4. If an import fails or blocks look broken, use "BUILD BY HAND" below, it takes 2-5 minutes per app.
   These .aia files were generated by script and not tested in App Inventor itself.

WHAT EACH FILE DOES
P01_HelloWorld       Label "Hello World!"
P02_UIDemo           TextBox + Button + Label + Notifier. Submit -> "Welcome, <name>!"
P03_LifeCycleDemo    Logs Initialize / ScreenOrientationChanged / BackPressed / OtherScreenClosed into a label
P04_IntentDemo       Screen1 -> Screen2 with data (open another screen with start value) + ActivityStarter opens website
P05_ListViewDemo     ListView of languages, tap -> "Selected: X"
P06_DialogDemo       Notifier.ShowChooseDialog Yes/No (Yes closes app) + ListPicker for colour list
P07_TextToSpeechDemo TextToSpeech.Speak(TextBox text)
P08_SmsDemo          Texting.SendMessageDirect (allow SMS permission; Companion may not allow, use built APK)
P09_DatabaseDemo     Add / View student marks stored in TinyDB
P10_StudentManager   Screen1 save student, Screen2 list, tap item -> confirm -> delete (TinyDB shared between screens)

DIFFERENCES FROM THE ANDROID STUDIO (JAVA) VERSION - SAY THIS IN VIVA IF ASKED
- App Inventor is visual block programming; Android Studio is Java/Kotlin + XML.
- No SQLite in App Inventor: P09/P10 use TinyDB (key-value storage on the phone). Real SQL needs CloudDB or Android Studio.
- No onStart/onResume/onPause/onStop events: P03 only shows the events App Inventor exposes.
- No long-press on ListView: P10 deletes on tap, with a confirm dialog.
- ShowChooseDialog allows only 2 buttons: the colour list in P06 uses ListPicker instead of AlertDialog.setItems.
- Intents: ActivityStarter (Action + DataUri) = implicit intent; "open another screen with start value" = explicit intent with putExtra.

BUILD BY HAND (if import fails)
Palette > drag components, set properties, then Blocks tab.
P01  Label1: Text "Hello World!", FontSize 28, FontBold.
P02  TextBox1 (Hint), Button1 (Text Submit), Label1, Notifier1.
     when Button1.Click: if is empty(trim(TextBox1.Text)) then Notifier1.ShowAlert "Please enter a name"
     else set Label1.Text to join("Welcome, ", TextBox1.Text, "!") and Notifier1.ShowAlert "Submitted".
P03  Label1, Notifier1. when Screen1.Initialize / ScreenOrientationChanged / BackPressed:
     set Label1.Text to join(Label1.Text, "event name", "\n").
P04  Screen1: TextBox1, BtnNext, BtnWeb, ActivityStarter1. Add Screen2 (Label1, BtnBack).
     BtnNext.Click: open another screen with start value (screenName "Screen2", startValue TextBox1.Text).
     Screen2.Initialize: set Label1.Text to join("Received: ", get start value). BtnBack.Click: close screen.
     BtnWeb.Click: set ActivityStarter1.Action "android.intent.action.VIEW", DataUri "https://www.dypatil.edu", call StartActivity.
P05  ListView1: ElementsFromString "Java,Kotlin,Python,C++,JavaScript,Swift,Dart,Go". Notifier1.
     ListView1.AfterPicking: Notifier1.ShowAlert join("Selected: ", ListView1.Selection).
P06  Button BtnAlert, ListPicker1 (Title "Pick a colour", ElementsFromString "Red,Green,Blue"), Notifier1.
     BtnAlert.Click: Notifier1.ShowChooseDialog("Do you want to exit the app?", "Exit", "Yes", "No", false).
     Notifier1.AfterChoosing: if choice = "Yes" then close application.
     ListPicker1.AfterPicking: ShowAlert join("You chose ", ListPicker1.Selection).
P07  TextBox1, BtnSpeak, TextToSpeech1, Notifier1. BtnSpeak.Click: if empty then alert else TextToSpeech1.Speak(TextBox1.Text).
P08  TxtPhone (NumbersOnly), TxtMsg, BtnSend, Texting1, Notifier1.
     BtnSend.Click: set Texting1.PhoneNumber, set Texting1.Message, call Texting1.SendMessageDirect, alert "SMS sent successfully".
P09  TxtName, TxtMarks, BtnAdd, BtnView, ListView1, TinyDB1. initialize global students to create empty list.
     Screen1.Initialize: set global students to TinyDB1.GetValue("students", create empty list).
     BtnAdd.Click: add items to list (global students, join(name, "   ", marks)); TinyDB1.StoreValue("students", global students).
     BtnView.Click: set ListView1.Elements to global students.
P10  Screen1: TxtName, TxtCourse, BtnSave, BtnList, TinyDB1. Save as P09 with join(name, " - ", course); BtnList opens Screen2.
     Screen2: ListView1, BtnBack, TinyDB1, Notifier1 (same global students, load in Initialize, set ListView1.Elements).
     ListView1.AfterPicking: ShowChooseDialog("Delete this student?", "Delete", "Yes", "No", false).
     Notifier1.AfterChoosing: if choice = "Yes": remove list item (global students, ListView1.SelectionIndex),
     StoreValue, refresh ListView1.Elements, alert "Deleted".

VIVA QUESTIONS (App Inventor)
Q: What is MIT App Inventor? A: Browser-based visual (drag-and-drop blocks) tool to build Android apps, from MIT.
Q: Designer vs Blocks? A: Designer = layout and components; Blocks = logic.
Q: What is the Companion? A: App on phone that runs your project live over Wi-Fi for testing.
Q: What is TinyDB? A: Non-visible component storing key-value data persistently on the device.
Q: Notifier? A: Shows alerts, message dialogs and choose dialogs.
Q: How do you pass data between screens? A: "open another screen with start value" and "get start value".
Q: ActivityStarter? A: Starts other apps/activities using Action + DataUri (implicit intent).
Q: Why is Texting permission needed? A: SEND_SMS is a dangerous permission, so Android asks the user.
Q: Limitations vs Android Studio? A: Less control, no SQLite/lifecycle callbacks, limited UI and performance tuning.
